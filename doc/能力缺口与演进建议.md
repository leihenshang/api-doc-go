# 能力缺口与演进建议

> 视角：**项目开发中「前后端共同使用」的 API 文档网站**（前端消费文档、后端维护契约、测试/外部同学查阅）。
> 结论基于对当前代码的逐项核查（证据见 §3 与 §6 能力矩阵），不是通用清单。
> 本文档同时充当**任务规划表**：§4 把缺口拆成可逐项执行的任务（T01…），带范围、 验收与状态。
> **后续路线以 `doc/下一步路线图.md`（2026-10-23）为准**：本文 T01–T20 是历史任务，新增能力（Try it、集合运行器/CI、契约治理、AI/MCP）在该路线图中统一排期。

## 一、结论速览

| 维度 | 现状 |
|---|---|
| 编写/治理侧 | **较完整**：项目/成员权限/多级分组/接口（请求头·参数·返回参数·样例·Markdown 说明）/项目文档/字段映射字典/备忘清单/公共属性/回收站/操作日志/OpenAPI 导入导出/Bruno 导入/cURL/变量与环境 |
| 消费侧（前端同学日常） | **明显欠缺**：没有在线调试、没有多语言示例、没有全局搜索、没有 Mock、没有免登录分享 |
| 契约治理侧 | **基本空白**：接口无版本/发布状态、无字段级 diff、**并发编辑会静默互相覆盖**、无契约一致性校验 |
| 协作/通知侧 | **几乎只有骨架**：无评论/评审/订阅；站内通知全仓只有「指派备忘」一个触发点 |
| 工程/运维 | **开发态**：无迁移版本表与执行器、JWT 无吊销、无限流、`/uploads` 公开、前端无 lint/测试/CI |

一句话：**它现在是一个"给文档作者用的后台"，还不完全是"给使用者用的平台"**——本轮优先补"用起来"和"改不坏"两类能力。

## 二、已有能力盘点（避免重复投入）

- **组织与权限**：用户（普通/管理员/超管）、项目成员 + 权限位（`PermQuery/Create/Update/Delete`）、负责人、项目级校验统一走 `ensureProjectPermission`。
- **接口文档**：`Api`（协议/方法/URL/请求头/请求参数/返回参数/返回样例/开发语言/Markdown 说明/来源标记）、多级分组、拖拽排序、软删除 + 回收站、字段映射自动回填、JSON 转表格。
- **文档**：Markdown 编辑（MdEditor/MdPreview）、置顶、浏览/点赞、软删除 + 回收站。
- **导入导出**：OpenAPI 导入（文件） / 导出（OpenAPI 3.0）、Bruno 集合目录导入（OpenCollection YAML）、cURL 生成。
- **变量与环境（Phase 1–2）**：三级变量（请求/项目/全局）+ 项目级环境；解析优先级；敏感值展示脱敏；详情页就地标记 + 环境切换；变量管理页。
- **辅助**：备忘清单（指派/状态/等级）、公共属性（标签字典）、站内通知（铃铛）、操作日志、图床上传、定时备份与日志清理、`bin/run.sh` 起停。

### 本轮（T01–T05，本次会话实施）

#### T01 变量 Phase 3：cURL 变量替换 ✅
- **目标**：复制 cURL 时可选「保留 `{{占位符}}`」或「替换为当前环境实际值」（含敏感值，服务端渲染）。
- **范围**：`service/variable.go`（新增 `renderVars`/`resolveTable`）、`service/export.go`（`ExportCurl` 增 `envID`/`resolve`）、`handler` + 路由（`/api/curl` 增可选参数）、前端 `ApiDetailView` 的 cURL 下拉。
- **验收**：`resolve=0` 输出与改动前**逐字节一致**（回归）；`resolve=1` 时占位符被替换、未定义项原样保留；含敏感值导出写审计日志（不记值）；`PermQuery` 成员可用。
- **依赖**：Phase 1–2（已就绪）。**成本**：小-中。

#### T02 全局搜索 ✅
- **目标**：跨项目搜索接口（名称/URL/说明）、项目文档（标题 + Markdown 正文）、项目名；结果分组展示、点击直达。
- **范围**：新增 `repository/search.go` + `service/search.go` + `handler/search.go` + 路由 `GET /api/search`；前端顶栏 `GlobalSearch.vue`（结果面板）。
- **权限**：管理员搜全量；普通用户只搜**自己参与的项目**（复用 `user_project`）。
- **验收**：搜关键词能命中接口名/URL/文档正文；只读成员搜不到未参与项目；空关键词返回空；结果点击落到 `/projects/:id/apis?api=..` 或 `/docs?doc=..`。
- **成本**：中。

#### T03 多语言示例代码 ✅
- **目标**：接口详情提供「代码」下拉：cURL（占位符/已替换）、fetch、axios、Go、Python。
- **范围**：新增 `service/code.go` + `GET /api/code?api_id=&env_id=&lang=&resolve=`（与 T01 共用 `renderVars`）；前端 `ApiDetailView` 的「代码」下拉（替换原 cURL 按钮）。
- **验收**：五种语言均可生成且语法正确；变量在 `resolve=1` 时替换、`0` 时保留；方法与 URL、请求头、查询参数、JSON 体都出现在片段中；敏感值不在 `resolve=0` 时出现。
- **成本**：小（复用 T01 渲染层）。

#### T04 并发编辑保护 ✅
- **目标**：接口/文档保存时若他人已改，明确报冲突而不是静默覆盖。
- **范围**：`dto`（`ApiUpdateReq`/`DocUpdateReq` 增可选 `expected_update_time`）、`service/content.go`（`UpdateApi`/`UpdateDoc` 比对库中 `update_time`，不一致返回 `CodeFailed` + 明确文案）、前端保存前带上载入时的 `update_time`，冲突时提示并支持「重新载入最新」。
- **兼容策略**：**仅在客户端传了 `expected_update_time` 时校验**——老客户端行为不变，不改现有契约。
- **验收**：A、B 同时打开同一接口，A 保存后 B 保存 → B 收到「该接口已被他人修改，请刷新后重试」；B 重新载入后保存成功；不带该字段的请求仍按原逻辑保存。
- **成本**：小。

#### T05 全局变量管理（Phase 3 剩余项） ✅
- **目标**：管理员在「公共属性」页维护应用级（跨项目）全局变量。
- **范围**：后端**无需改动**（`GET/POST/PUT/DELETE /api/variable?scope=3` 已就绪，写操作仅管理员）；前端 `views/PropertyView.vue` 改为「标签字典 / 全局变量」双页签，复用变量表格与弹窗。
- **验收**：非管理员看不到「全局变量」页签；管理员可增删改、可标记敏感；全局变量在各项目详情页参与解析（优先级最低）且被项目变量覆盖。
- **成本**：小。
