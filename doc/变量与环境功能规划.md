# 变量与环境功能规划

> 目标：为 api-doc-go 增加**三级变量**（请求变量 / 项目变量 / 全局变量）与**环境**能力，并在接口详情页与接口列表中就**就地/直观展示**变量解析结果。
> 决策已全部拍板（2026-09-26，共 10 条，见 §9），无遗留待定项。
> 依据：现有代码约定（`model/repository/service/handler/dto/router` 五层、软删除 `is_deleted`、局部唯一索引、`project.can(PermXxx)`、配置走环境变量 + 默认值）与 `doc/bruno-环境变量与变量功能清单.md` 的 Bruno 能力对照。

---

## 一、范围

### 1.1 本版要做（v1）
| # | 能力 | 说明 |
|---|---|---|
| 1 | 请求变量（API 级） | 挂在单个接口上，仅该接口可用；随接口详情页编辑 |
| 2 | 项目变量（项目级） | 项目内共享；**按环境取值**，另支持"通用（不限环境）"兜底 |
| 3 | 全局变量（应用级） | 管理员维护，跨项目共享；项目内只读可见，可被项目变量覆盖；**不分环境** |
| 4 | 环境管理 | 项目级多环境（dev/test/prod）+ 颜色 + 默认环境；用户当前环境按项目记忆；**有引用不可删** |
| 5 | 详情页解析与展示 | `{{var}}` 在 URL/请求头/参数中就地高亮、悬停显示来源与取值、未定义告警、空值中性提示 |
| 6 | **接口列表可见性** | 接口列表新增「变量」列：显示请求变量条数与未定义变量条数（未定义用告警色），悬停显示变量名清单 |
| 7 | cURL 变量替换 | 复制 cURL 可选保留占位符 / 替换为当前环境实际值；**所有可查看成员都可用**（含敏感值，见 §4.4） |
| 8 | 敏感值展示脱敏 | `is_secret=1` 的值只在变量管理页与悬停提示中显示掩码；**库中为明文（v1 不加密，见 §3.4）** |

### 1.2 本版不做（备选/已明确不做）
- 接口详情页新增独立「变量」一节（你未选；若后续想要，只需在 `ApiDetailView.vue` 加一个 `data-sec` 段并登记大纲，无数据模型改动）。
- **"从未定义变量一键创建"**（决策 8：无需）；详情页仍保留"本接口有 N 个未定义变量"的轻提示，但不提供一键建变量。
- 左树叶子的变量标记（本次只做接口列表；叶子标记复用同一组件即可，成本低，若你要可随时加）。
- **敏感值的服务端加密**（决策 5 变更：v1 明文入库，只做展示脱敏；将来要加时不需要改表结构，见 §3.4）。
- 动态变量（`{{$randomUUID}}` 等 faker 系列）、Prompt 变量（`{{?xxx}}`）、对象/数组下标访问（`{{obj.a}}`、`{{arr[0]}}`）、`extends` 环境继承。
- 密钥轮换/多版本密钥、secret manager（Vault/AWS/Azure/GCP）集成。

### 1.3 与 Bruno 的对应关系
| Bruno | 本项目 v1 | 差异 |
|---|---|---|
| Request Variables | 请求变量（API 级） | 一致（`bru.getRequestVar` 仅读 → 本项目可直接在详情页编辑） |
| Collection Variables | 项目变量 + 环境维度 | Bruno 的集合变量不分环境，本项目把"按环境"做进项目变量（更像 Bruno 的 Environment Variables） |
| Environment Variables | 环境 + 项目变量(`env_id`) | 合并为一层，减少概念 |
| Global Environment Variables | 全局变量（应用级） | 一致（跨项目共享、管理员维护），但 v1 不分环境 |
| Runtime Variables | 不做 | 本项目是文档工具，无"运行时"语义 |
| `vars:secret` | `is_secret=1` + 展示脱敏 | 本项目是**团队共享**的明文存储，比 Bruno（只保证不写入集合文件、值仅存本机）弱，需靠 DB/备份访问控制兜底（见 §4.4 取舍说明） |

## 二、变量解析规则

### 2.1 语法与命名
- 占位符：`{{变量名}}`，可在 **URL、请求头 value、请求参数（示例/默认值列）** 中出现。
- 变量名规则（校验用正则）：`^[A-Za-z_][A-Za-z0-9_]{0,63}$`
  - 禁止 `.`、`[`、`]`（v1 不支持属性/下标访问）
  - 禁止 `$` 前缀（为将来兼容 Bruno 动态变量 `{{$randomXxx}}` 保留，避免歧义）
  - 禁止空白与中文（如需中文名，放到"描述"里）
- 大小写敏感。

### 2.2 解析优先级与三类"取值状态"
```
优先级（高 → 低）
1. 请求变量（api_id = 当前接口）
2. 项目变量（project_id = 当前项目, env_id = 当前环境）
3. 项目变量（project_id = 当前项目, env_id = 0  —— 通用兜底）
4. 全局变量（scope = 全局，应用级单值）
—— 都未命中 → 未定义
```
命中后按值的三种状态分别处理（**决策 7**）：

| 状态 | 判定 | 替换结果 | UI 提示 |
|---|---|---|---|
| 有值 | `value` 非空 | 用实际值替换 | 强调色 + 虚线下划线 |
| **空值** | `value` 为空串 | 替换为**空串** | **中性色**标记 + tooltip「空值」（不告警） |
| 未定义 | 四层都未命中 | **原样保留** `{{var}}` | **黄色告警**标记 + tooltip「未定义变量」 |

其他规则：
- **禁用（`enabled = 0`）视为不存在**（跳过该层，继续向下查找；若最终未命中即"未定义"）。
- 不做递归解析（变量值里再写 `{{y}}` 不展开，v1 直接输出原文，避免循环问题）。
- `is_secret=1` 只影响**展示与接口回传**（掩码），**不影响解析结果**：cURL 替换时正常使用该值。

### 2.3 当前环境的选择与记忆
- 每个项目有**默认环境**（`is_default = 1`），项目未选过环境时用它。
- 用户在项目内选择的环境存 **pinia store + localStorage**（键：`apidoc.env.<projectId>`），刷新/重进保持；与 Bruno"最近选择优先于默认环境"一致。
- 环境切换只影响**展示、解析结果与列表徽标**，不改写任何接口数据（接口里始终保存 `{{var}}` 原文）。
- 环境被删除时，前端清除本地选择并回落到默认环境。

### 2.4 展示形态

**A. 接口详情页**
| 位置 | 行为 |
|---|---|
| URL 栏 | `{{var}}` 用强调色 + 虚线下划线；悬停 tooltip：`变量名 · 来源（请求级/项目级/全局） · 当前值`；secret 值显示 `••••••` |
| 请求头表格 value 列 | 同上（表格内联小标记，不换行） |
| 请求参数表格 | 对"示例"列做同样标记 |
| 空值变量 | 中性色（灰）标记 + tooltip「空值」 |
| 未定义变量 | 黄色（警示色）标记 + tooltip「未定义变量」 |
| 环境切换器 | 详情页名称栏/URL 栏旁下拉（`EnvPicker`），切换后所有标记实时重算 |
| 复制 cURL | 按钮改**下拉**：`复制 cURL（保留 {{占位符}}）` / `复制 cURL（替换为实际值）` |
| 顶部轻提示 | `本接口有 N 个未定义变量`（可点击跳到项目变量管理页并按关键词筛选，**不提供一键创建**） |

**B. 接口列表（决策 9：显示）**
| 位置 | 行为 |
|---|---|
| 接口列表新增「变量」列 | 显示：请求变量条数（如 `2`）+ 未定义条数（如 `1` 用告警色）；均为 0 时显示 `—` |
| 悬停 | tooltip 列出变量名：`请求变量：token` / `未定义：baseUrl`（最多 8 个，多余显示 `等 N 个`） |
| 数据来源 | 新增批量接口 `GET /api/variable/summary`（见 §4.3），**不改动现有列表接口契约** |
| 环境联动 | 切换当前环境后，列表徽标（尤其"未定义"）随之刷新 |
| **落点（实现调整）** | ~~接口列表当前由**左树 `SectionTree`** 承载（工作台改版后已无接口表格），因此「变量」徽标落在**树叶子行**~~ → **2026-09-26 按需求整体移除该展示**（左树不再显示变量统计）；`summary` 接口与 `VarBadge` 组件保留备用 |

## 三、数据模型

### 3.1 新增表 1：`variable_env`（项目级环境）
| 字段 | 类型 | 说明 |
|---|---|---|
| `id` / `is_deleted` / `create_time` / `update_time` | 内嵌 `BaseModel` | 与全库一致 |
| `project_id` | uint64 | 所属项目 |
| `name` | string(100) | 环境名（dev/test/prod） |
| `description` | text | 说明 |
| `color` | string(20) | 颜色标记（`#RRGGBB`，空则前端给默认色） |
| `is_default` | int8 | 是否项目默认环境（同项目由 service 层保证唯一） |
| `priority` | int | 排序 |

索引：
- 局部唯一：`uk_var_env_name (project_id, name) WHERE is_deleted = 0`
- 普通：`idx_var_env_project (project_id)`

### 3.2 新增表 2：`variable`（变量，三级共用一张表）
| 字段 | 类型 | 说明 |
|---|---|---|
| `id` / `is_deleted` / `create_time` / `update_time` | 内嵌 `BaseModel` | 一致 |
| `scope` | int8 | `1` = 请求变量，`2` = 项目变量，`3` = 全局变量 |
| `project_id` | uint64 | 项目级/请求级必填；**全局变量固定 0** |
| `api_id` | uint64 | 仅 `scope=1` 填接口 id，其余 0 |
| `env_id` | uint64 | 仅 `scope=2` 生效：0 = 通用，>0 = 绑定某环境；`scope=3` 固定 0（全局变量不分环境） |
| `name` | string(100) | 变量名（规则见 §2.1） |
| `value` | text | 变量值（**明文存储**，含敏感值；v1 不加密，见 §3.4）。接口一律不回传敏感值的明文 |
| `description` | text | 说明 |
| `is_secret` | int8 | 敏感值标记：1 = 展示/回传脱敏（**不是安全边界**，库里是明文） |
| `enabled` | int8 | 默认 1；0 = 停用（解析时跳过） |
| `priority` | int | 排序 |

索引：
- 局部唯一：`uk_variable_key (scope, project_id, api_id, env_id, name) WHERE is_deleted = 0` —— 同层同环境不允许重名
- 查询用：`idx_variable_scope (scope, project_id, api_id)`、`idx_variable_name (name)`

> 设计取舍：**单表 + `scope`** 而不是三张表 —— 三级变量的字段完全同构（名称/值/描述/停用），共用一张表可让"解析优先级"用一条查询（`scope IN (1,2,3) AND name = ?`）算完，管理页也能复用同一套 CRUD；代价是局部唯一索引带 5 列。

### 3.3 迁移与 AutoMigrate
- `server/internal/model/variable.go`（新增两实体，含 `TableName()`）
- `server/internal/database/migrate.go`：`entities` 列表追加 `&model.VariableEnv{}`、`&model.Variable{}`
- 迁移脚本（本项目强制要求补）：`server/migrations/sqlite/0007_variables.{up,down}.sql`、`server/migrations/postgres/0007_variables.{up,down}.sql`（一个版本号内建两张表 + 索引）

### 3.4 敏感值处理（决策 5 变更：v1 不加密）
**v1 行为**：`is_secret=1` 的值**明文入库**，只做三件事：
1. 变量管理页与所有读接口（列表 / `resolve` / `summary`）**只返回掩码** `••••••` + `has_value`，前端拿不到明文；
2. 悬停 tooltip 对敏感变量不显示值；
3. 通过 cURL 替换实际导出敏感值时写 `recordOp` 审计（只记变量名与接口名，不记值）。

**明确风险与运维要求**（已在 §9 决策记录中留痕）：
- `is_secret` 是**展示脱敏标记，不是安全边界**；凡是能读数据库或备份文件的人都能看到明文
- 因此：数据库文件/备份（`data/` 与 `BACKUP_DIR`）需按敏感数据管理（权限最小化、不随仓库提交；`server/.gitignore` 已忽略 SQLite 主库 `*.db`、旁路文件 `*.db-*`（`-wal/-shm`）、备份 `*.db.bak*` 与 `data/backups/`（2026-09-26 补齐）），生产环境的 DB 访问凭据走环境变量

**将来要加加密时（无需改表结构）**：
- 新增 `crypto` 包（AES-256-GCM）+ 配置项 `SECRET_ENCRYPT_KEY`（`internal/config` 的 `getEnv` 约定）
- 在 service 的写入/读取路径各加一层编解码；密文可带版本前缀（`v2:...`）以实现密钥轮换
- 历史明文行按"无前缀即明文"兼容，首次写入时升级为密文
- 表结构（§3.2）与接口契约（§4）都不需要改动，因此**现在不加密不影响后续演进**

## 四、后端接口设计

沿用现有约定：**静态路径 + query 传 id**、统一 `{code,msg,data}`、鉴权走 `middleware.Auth`、按模块 `g.Group("/xxx")` 分组。

### 4.1 环境 `variable-env`
| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| POST | `/api/variable-env` | 新建环境 | `PermCreate` |
| GET | `/api/variable-env?project_id=` | 环境列表（含 `is_default`、各环境变量计数） | `PermQuery` |
| PUT | `/api/variable-env` | 改名/描述/颜色/优先级 | `PermUpdate` |
| PUT | `/api/variable-env/default` | 设为默认（同项目互斥，事务内清旧默认） | `PermUpdate` |
| GET | `/api/variable-env/references?id=` | **删除前预检**：返回引用该环境的资源清单（见 §4.6） | `PermQuery` |
| DELETE | `/api/variable-env?id=` | 删除；**有引用一律拒绝**并列出引用明细 | `PermDelete` |

### 4.2 变量 `variable`
| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| POST | `/api/variable` | 新建（`scope/project_id/api_id/env_id/name/value/...`） | 见 §4.5 |
| GET | `/api/variable?project_id=&scope=&api_id=&env_id=&keyword=` | 列表；**secret 值只返回掩码 + `has_value`** | `PermQuery` |
| PUT | `/api/variable` | 修改值/描述/停用/改名；`value` 省略表示"不变" | 见 §4.5 |
| DELETE | `/api/variable?id=` | 软删除 | 见 §4.5 |
| GET | `/api/variable/resolve?project_id=&api_id=&env_id=` | **解析表**：返回该接口可见的全部变量（含来源层），secret 值一律掩码 | `PermQuery` |

`resolve` 返回结构（示意）：
```json
{
  "env_id": 3,
  "items": [
    { "name": "token",   "value": "abc",       "scope": 1, "source": "request", "is_secret": 0, "has_value": true,  "enabled": 1 },
    { "name": "baseUrl", "value": "https://dev.api.com", "scope": 2, "source": "project", "is_secret": 0, "has_value": true, "enabled": 1 },
    { "name": "apiKey",  "value": "••••••",    "scope": 3, "source": "global",  "is_secret": 1, "has_value": true,  "enabled": 1 },
    { "name": "remark",  "value": "",          "scope": 2, "source": "project", "is_secret": 0, "has_value": false, "enabled": 1 }
  ]
}
```
> 同名只返回**最高优先级**的那条（前端只关心"当前生效值"）；`has_value=false` 即"空值"状态（对应 §2.2）。

### 4.3 列表徽标批量接口 `summary`（决策 9）
`GET /api/variable/summary?project_id=&env_id=&api_ids=1,2,3`
```json
{
  "env_id": 3,
  "items": {
    "12": { "defined": ["token"], "undefined": ["baseUrl"], "request_count": 1, "undefined_count": 1 },
    "13": { "defined": [], "undefined": [], "request_count": 0, "undefined_count": 0 }
  }
}
```
- `api_ids` 上限 **200**（超出由前端分批调用），仅统计传入的接口，避免全表扫描
- 服务端实现：一次查出这些接口的 `api_id → 请求变量`（`scope=1`）与项目/全局变量（`scope IN (2,3)`），再用与 `resolve` **同一个** `collectVarNames(text)` 解析器扫描 URL/请求头/参数，得到 `defined/undefined`
- 复用 `resolve` 的优先级与"空值/停用"规则，保证列表徽标与详情页展示**永远一致**
- 现有 `GET /api/api`（列表）与 `GET /api/curl` 契约都不变

### 4.4 cURL 兼容扩展（决策 10：所有可查看成员都能执行）
现有 `GET /api/curl?api_id=`（`service/export.go:118` `ExportCurl`）扩展两个可选参数：
- `env_id=`（默认 0）：使用哪个环境做替换
- `resolve=`（默认 `0`）：`0` = 保留 `{{}}` 原文（**默认行为不变，保证兼容**）；`1` = 用解析值的**明文**替换（含敏感变量，服务端直接取值渲染）

权限：**沿用 `PermQuery`**（能查看接口即可导出），不额外要求 `PermUpdate`；每次 `resolve=1` 且结果涉及敏感变量时 `recordOp(..., "export", "导出含敏感变量的 cURL：apiKey, token")` 作为审计留痕（只记变量名，不记值）。

> 已接受的取舍：项目成员可通过该入口取得团队共享的敏感值（cURL 里是明文），且库中本身也是明文。缓解手段为**审计留痕**（操作日志可查谁在何时导出了含哪些敏感变量的命令）+ **DB/备份访问控制**；若将来要收紧，可加配置开关切回 `PermUpdate` 门槛（接口与前端无需改动）。

实现上抽出 `renderVars(text, table) string` 与 `renderCurl(a, table, resolve) string`，`ExportCurl` 内对 URL/请求头/请求体各调用一次；新增可选参数由 handler 绑定，不改现有调用语义。

### 4.5 权限矩阵
| 变量层 / 资源 | 查看 | 新增/修改/删除 |
|---|---|---|
| 请求变量（API 级） | `PermQuery` | `PermUpdate`（改内容即改接口内容） |
| 项目变量（项目级） | `PermQuery` | `PermCreate` / `PermUpdate` / `PermDelete`（与 `field_mapping` 完全一致） |
| 全局变量（应用级） | 所有登录用户只读 | **仅管理员**（`user.type` 为管理员/超管） |
| 环境 | `PermQuery` | `PermCreate`（新建）/ `PermUpdate`（编辑、设默认）/ `PermDelete`（删除） |
| cURL 导出（含敏感值） | `PermQuery`（决策 10） | — |

校验复用 `ensureProjectPermission(ctx, userID, typ, projectID, need)`；全局变量写操作新增 `ensureAdmin(typ)` 小助手（service 层，单测覆盖）。

### 4.6 环境删除的引用检查（决策 6）
**预检接口** `GET /api/variable-env/references?id=`：
```json
{
  "env": { "id": 3, "name": "dev", "is_default": true },
  "variables": [
    { "id": 11, "name": "baseUrl", "scope": 2, "enabled": 1 },
    { "id": 12, "name": "token",   "scope": 2, "enabled": 0 }
  ],
  "blocked": true
}
```
**删除接口** `DELETE /api/variable-env?id=` 服务端**再查一次**（防并发），有引用则拒绝：
- 有变量：`newBiz(CodeFailed, "环境「dev」被 3 个变量引用，无法删除：baseUrl、token、apiKey；请先删除或改绑这些变量")`
- 是默认环境**且项目仍有其它环境**：`newBiz(CodeFailed, "「dev」是项目默认环境，请先把其它环境设为默认")`
- 两条同时命中时，**先报默认环境**（改名/换默认后即可删除）
- **唯一的默认环境允许删除**（实现补充，2026-09-26）：项目只有一个环境时删除它会让项目回到"无环境"状态（项目变量只能用"通用"值），这是合法诉求，不应用"先改默认"卡住；因此默认环境的拦截条件是 `is_default = 1 且 count(环境) > 1`
- 无引用：软删除成功；同时 `recordOp` 记日志

**前端配合**：删除确认弹窗先调 `references` —— 有引用时禁用"确认删除"，直接列出引用清单（变量名可点击跳到变量管理页并按该环境筛选）；删除的若正是本地当前环境，清除 `localStorage` 并回落到默认环境。

**可扩展性**：引用汇总统一收敛在 `service` 的 `envReferences(ctx, envID)`（返回 `[]EnvRef{Type, ID, Name}`），v1 只实现 `variable` 一种类型，将来若有其它表引用环境只需在其中追加分支。

### 4.7 契约文档与日志

- 写操作调用 `recordOp(...)`；在 `model` 里补 `LogObjectVariable` / `LogObjectVariableEnv` 常量（如现有常量块需要）

## 八、测试要点（最小集合）

**后端单测（`internal/service`）**
1. 优先级：四层同名时取请求级 → 删掉请求级后取项目级(当前环境) → 删掉后取通用 → 再删取全局
2. 环境隔离：dev 与 test 同名不同值，切 `env_id` 结果不同
3. 未定义 / 空值：`resolve` 对未定义不返回该名；空值返回 `has_value=false`；`renderVars` 对未定义保留 `{{x}}`、对空值替换为空串
4. 停用：`enabled=0` 被视为不存在，回落到下一层
5. 唯一约束：同层同环境重名 → 业务错误 + 明确文案；不同环境同名 → 允许
6. 权限：非管理员写全局变量被拒（`CodeForbidden`）；无 `PermUpdate` 写请求变量被拒；**`PermQuery` 用户请求 `resolve=1` 成功**（决策 10）
7. 默认环境：设默认后同项目唯一；删除默认环境被拒（`先改默认` 文案）
8. **引用拦截**：环境仍有变量时删除被拒，错误文案包含变量名清单；`references` 返回结构正确（含 `is_default`）
9. **敏感值脱敏**：`is_secret=1` 在列表 / `resolve` / `summary` 中均以掩码 + `has_value` 返回（断言响应体不含明文）；`resolve=1` 的 cURL 中使用明文；审计日志只含变量名
10. **summary**：多接口批量结果的 `defined/undefined` 与 `resolve`（同环境）逐接口一致；`api_ids` 超上限被拒或分批；无变量的接口返回空数组
11. 回归：`ExportCurl` 在 `resolve=0` 下输出与旧实现一致

**前端手测**
- 环境切换 → 详情页标记与列表徽标同步刷新；刷新页面后仍记住当前环境；删除当前环境后回落到默认环境
- 敏感变量在列表与悬停 tooltip 中为掩码；编辑弹窗可回显明文；cURL 替换后包含真实值
- 空值（中性）与未定义（黄色告警）视觉可区分
- 列表「变量」列条数与详情页一致；tooltip 变量名清单正确
- 删除环境时被引用清单可见、确认按钮禁用、变量名可点击跳转
